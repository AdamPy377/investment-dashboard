# Investment dashboard

A phone-friendly Flask + SQLite dashboard for two independent portfolios. The administrator login can enter and edit both portfolios; the viewer login sees only its own portfolio. Records include holdings, cash accounts, interest, dividends, transactions, documents, allocation, historical performance and current account reconciliation.

**Deployment:** See [PORTAINER-SETUP.md](PORTAINER-SETUP.md) for the GitHub → Portainer → homelab walkthrough. The container serves HTTP on host port 3005 by default.

## Using the dashboard

Choose your portfolio from the selector at the top, then open **Manage**. Trades use a short form with type, date, account, holding, quantity, price and brokerage. The cash activity tab covers deposits, withdrawals, dividends, interest, fees, transfers and currency exchanges; destination and received amount appear only when applicable. The account, holding, document and balance check lists have Edit and Delete controls. Prices and USD/AUD rates can also be corrected or deleted. Accounts with linked transactions, documents or balance checks cannot be deleted until those records are moved or removed, and a holding with linked trades or documents cannot be deleted. A holding shared by both portfolios is edited for both.

Start by selecting a portfolio in **Manage**. Add separate cash accounts for AUD and USD (for example Stake AUD and Stake USD), plus an investment bank account if needed. An account always holds cash only. Enter the broker name on its account record; buys and sells link shares to that broker through the account used for settlement. Shares appear only under Holdings and the portfolio total, never as part of a cash account balance. Add AU or US holdings, then enter the complete transaction history. Deposits and withdrawals are external contributions. Transfers between accounts do not count as returns. If AUD cash is exchanged for USD cash, record a currency exchange with the sent and received amounts. An external deposit directly into a USD account can carry its actual AUD per USD rate; leaving it blank uses the dated reference rate when one is available. Buys and sells in a USD account spend or return USD cash directly and never need a trade FX rate. Sales exceeding the shares held in that broker account are rejected.

Use **Manage → Dividend reinvestment** to record a dividend payment and its share allotment in one action, including the gross dividend, withheld tax, AUD franking credit, shares, allotment price, brokerage and separate payment/allotment dates. Two linked ledger entries are created in a single database transaction. Edit or delete them together in that tab; the Transactions page links back to it. The net dividend goes into a separate DRP balance for that holding and broker. The new shares are paid for from that balance; any remainder carries to the next reinvestment and is never shown as spendable broker cash. The DRP balance is included in portfolio value and shown separately on the overview and holding page. An allotment cannot spend more than this dividend plus earlier carried amounts. If you already matched a broker cash balance while using v2.5 DRPs, review that balance check after this upgrade: a correction entered to remove a DRP residual from broker cash might now be unnecessary. The allotted shares form a new parcel in the financial-year schedule. Dividend income remains recorded even though no cash was withdrawn.

Upload PDFs, images and CSV files in **Manage** and attach each file to a holding, broker account and/or tax year. The Documents page filters them. A portfolio's viewer cannot access the other portfolio's documents by URL. The 20 MB file limit can be raised in `app.py` if needed.

**CSV import:** Manage → CSV import accepts this dashboard's own transaction export when its account and holding IDs still exist in the same database, or a UTF-8 CSV using the downloadable template. Supported template columns are date, type, account, symbol, quantity, price, amount, fee, tax, franking_credit, target_account, target_amount, fx_rate and note. Date is YYYY-MM-DD; amounts are nonnegative numbers. Account names and holdings must already exist and match exactly. Preview flags unknown rows, skips exact economic duplicates, and excludes balance-check cash corrections. If any row has an error the whole file is blocked until fixed; otherwise the accepted rows are inserted as one database transaction and audited. Reimporting the same file will not create the same transactions again. This is a common CSV template, **not** a verified direct parser for raw Stake or Pearler exports; use their export to fill the template or provide a sample to add a verified mapping. Do not import dashboard exports from one portfolio into another.

**Financial years and returns:** Documents includes an Australian July–June summary for the signed-in portfolio: AUD income, withholding, franking credits and realised sales matched to purchase parcels using FIFO within each broker account. Enter franking credits alongside AUD dividends; the selected report can be downloaded as CSV. The report shows which gains passed the twelve-month holding flag, but does not apply a tax discount or calculate tax payable. Check trade dates, parcel choices, ETF AMMA/annual tax statement adjustments, trust ownership and historical USD/AUD rates with your accountant. The homepage shows a money-weighted annualised return (XIRR) and cumulative time-weighted return, using dated external deposits and withdrawals and the saved valuations. Missing deposits, cash corrections and unpriced dates can make returns unavailable or misleading. Complete cash activity before relying on them.

## Market data and calculations

- Yahoo Finance daily prices are fetched with `yfinance`, without an API key. On first refresh or worker start, every holding with a buy transaction is backfilled from its **earliest buy in either portfolio**, including holdings since sold (only through their last sale). New closes are checked from 5 pm in each market's own time zone (Sydney/New York; daylight saving handled); publication can take longer. The worker wakes every 15 minutes, and `REFRESH_SECONDS` overrides its check interval. After a complete backfill, recent prices are refreshed automatically, while feed errors retry at most four times per market day with two hours between attempts. Yahoo Finance is an unofficial source and may change or limit availability. Existing manual prices always take priority for the same date. Old Alpha Vantage/EODHD rows remain in the database but are replaced where Yahoo returns a daily close. Set a Yahoo symbol override in **Manage → Holdings** if the default ticker (`VAS.AX` or `AMD`) is incorrect. If a holding does not update, choose **Manage → Prices & FX → Refresh feed** to see a ticker-specific error, and inspect the `portfolio-price-worker` logs in Portainer. Changing a ticker or override removes its old automatic prices and downloads its history again; manual prices remain intact.
- The app stores daily **Close**, without dividend adjustment, because dividends are recorded separately as transactions. Prices still reflect Yahoo's treatment of stock splits; enter split transactions to keep quantities accurate. The graph carries the latest available trading-day close over weekends, and leaves dates before the first available close unvalued. Historical USD/AUD reference rates from Frankfurter are still downloaded separately from the earliest USD transaction, and manually entered rates take priority. Transactions, cash corrections and FX rates must be complete for a historical portfolio value to be accurate.
- Each holding page embeds TradingView's Symbol Overview chart with a link if the embed cannot load. **Manage → Holdings** lets you set its TradingView symbol. The holding page lists the five most recent saved closes; its duplicate price graph was removed. The previous sandboxed embed stopped displaying for some users, so this uses TradingView's standard embed script in the dashboard page again. That third-party script executes in the signed-in page; only use it if you trust TradingView with access to the page and session. TradingView's chart data can differ from the portfolio's saved prices. The home page lists holdings first, with cash balances beside an allocation pie.
- The portfolio history has separate **Value** and **Profit after contributions** views, each with its own scale. Hover or drag over a date to see its portfolio value, net external contributions and profit; purple dots mark changes in net contributions. Value includes deposits and cash, so a large deposit can create a real upward step; the profit view makes performance easier to inspect. A balance-check cash correction also changes the displayed profit. Manage → Prices & FX initially lists the latest saved close for each holding; use **Show all prices** to edit older closes. The three most recent USD/AUD rates are shown.
- Historical chart days with a missing holding price are left blank; no price is guessed. The dashboard shows the oldest current holding price and flags missing or older-than-expected weekday quotes (holidays can produce a temporary warning). 'Latest session move' values today's holdings using each security's two most recent saved closes and the two most recent USD/AUD reference rates, including USD cash exposure; it excludes trades and dividends. The label does not mean the last 24 hours. A holding with fewer than two closes, or missing required FX, shows no session move.
- Dated USD/AUD rates convert USD cash and holdings into AUD for the portfolio value and history. They do not create currency exchange transactions. A trade in a USD account uses only USD.
- Portfolio value includes holdings and cash converted to AUD. All-time profit is portfolio value less historical external contributions, including recorded dividends, interest, trading costs and fees. Unrealised holding gain is based on a pooled average cost **within each broker account**. These calculations are for monitoring, not tax reporting.
- Balance checks always compare **cash only** to the reported bank or broker cash balance. A check dated today can set that account’s cash to the reported amount using a linked cash correction. Editing and reapplying a check updates the same correction; deleting it removes the correction. Checks created before this version are now compared against cash, but previous corrections are not silently changed; review and rematch today’s checks if needed. Historical checks do not change today’s cash. Corrections affect displayed profit and appear in Transactions, but are not external deposits. If the difference comes from a missing deposit or incorrect transaction, enter or correct that transaction instead.

Back up the entire data directory, including the SQLite database and the `documents` folder. The included backup service makes a daily online SQLite copy and copies documents to the separately mounted backup directory, retaining 30 days by default. A document uploaded during the copy may only appear in the next backup; keep another copy of irreplaceable statements.

Transactions can be exported as CSV by the administrator. Edits and deletions are recorded in `transaction_audit` in the database. Cash corrections linked to a balance check are managed through that check; older corrections created before this update remain ordinary transactions. Each user can change their own password from **Settings** in the header. The admin can reset the viewer password there after confirming the admin password; reset signs out existing viewer sessions. On first startup, missing or short account passwords now fail the container boot with an explicit error. The viewer sees Overview, Transactions, Cash balances and Documents; Reconcile and Manage require admin access.

Run `pip install -r requirements-dev.txt` and `pytest -q` to exercise the ledger and authentication regression tests.

## Updating an existing Portainer installation

Replace the repository files and redeploy the stack from its GitHub source. Keep the same Portainer environment variables and mounted data and backup directories. The application adds its new transaction FX column automatically on startup; do not delete the SQLite database or the documents directory. If Portainer offers **Re-pull image**, leave it off: this stack builds the local `investment-dashboard:local` image from the repository rather than pulling it from a registry.
